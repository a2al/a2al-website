これは**持続接続**のチャネルです。長期にわたって保つ必要のある TCP 接続にはトンネルを使います。相手が NAT の内側にいて公開 IP がなくても、ローカルのサービスにつなぐのと同じように使えます。SSH、データベースクライアント、長いセッションのいずれにも適します。

典型的な用途：相手のマシンへ SSH して原因を調べる。手元のデータベースクライアントで相手の内部ネットワークのデータベースにつなぐ。デバッグ中に手元のポートを遠隔のサービスに接続する。

```bash
a2al tunnel open <相手のAID> --local-port 2222
# Tunnel:  127.0.0.1:2222
# ID:      <トンネルID>          # 閉じるときは a2al tunnel close <トンネルID>

ssh -p 2222 user@127.0.0.1        # 実際にお使いのクライアントで構いません
```

## 仕組み

- トンネルは**ポート**単位で確立します。同じ組み合わせ（自分の AID、相手の AID、ポート）は同じトンネルを使い回し、重複して張りません。
- 2本目が必要なときは別の `--local-port` を指定します。
- 使い回す前に短い疎通確認（約8秒）を行い、失敗すれば張り直します。切断への対処は不要です。
- アイドルタイムアウトは既定で **6分** で、`--idle-timeout` で調整できます。
- 接続の確立には**双方がオンライン**である必要があります。相手がオフラインになりうる場合は[ノート](/ja/docs/user/messaging)に切り替えてください。

**AI アシスタント（MCP）**：`a2al_tunnel_open` / `a2al_tunnel_close`。
