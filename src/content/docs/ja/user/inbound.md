これは**リクエスト／レスポンス**型チャネルのもう一端です。自分のマシンで動いているサービス——ローカルの LLM、社内 API、自動化スクリプト——を AID にバインドします。バインドすれば、他のエージェントや人が**アドレスだけ**で呼び出せます。ポート開放も、ドメイン名も、公開 IP も要りません。

典型的な用途：ローカルのモデルサービスを同僚や他のエージェントに使ってもらう、社内にすでにあるエンドポイントをインターネットに出さずに指定した相手へ AID で開放する。

## 3ステップでバインド

```bash
a2al register                                   # 1. アイデンティティの作成（すでにあれば省略可）
a2al inbound bind --addr 127.0.0.1:8080         # 2. ローカルサービスをバインド（実際に待ち受けているポートを指定）
a2al publish lang.translate --name "翻訳" --brief "中国語と英語の相互翻訳"   # 3. サービス名の公開（任意）
```

`--addr` にはサービスが**実際に待ち受けている**アドレスを指定します。`2121` は a2ald の API ポートなので、バインドには使えません。

3 は公開検索のための手順です。AID を指定した相手にだけ渡すなら省略できます。

## 相手からの呼び出し方

```bash
a2al get <あなたのAID> /your/api/path      # AID が分かっている場合：直接呼び出す
a2al search lang.translate                # AID が不明な場合：サービス名で検索する
```

## 期待される結果

相手が `a2al get <あなたのAID> /.well-known/agent.json` を実行し、あなたのサービスが返す JSON を受け取ります。相手の IP、ネットワーク、NAT の構成は結果に影響しません。

## サービスを利用可能なまま保つ

- **バインドはアイデンティティとともに保存されます**：バインド情報は a2ald のデータディレクトリに保存され、同じディレクトリから再起動すれば自動的に復元されます。
- **公開記録には有効期限があります**：a2ald が停止すると、公開済みの記録は約 **1時間** で期限切れになり、検索にも一致しなくなります。長期にわたって検索可能にしたい場合は daemon を常駐させてください（Windows / macOS は `a2ald service install`、Linux はデプロイの各ガイドを参照）。
- **アクセス制御**：呼び出せる相手を絞る場合は ACL を使います。**発見できることは、呼び出せることと同じではありません。**
