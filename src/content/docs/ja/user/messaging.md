メッセージ系のチャネルには三つの形態があります。三つに共通する前提は同じです。**先に解消すべきネットワーク設定はなく**、アドレスがあれば十分です。

| 形態 | チャネル |
| --- | --- |
| 単方向メッセージ | **ノート**（note）——片方向の伝達。相手はオフラインでもよい |
| 双方向セッション | **会話**（chat）——双方向のやりとり。履歴と既読状態をもつ |
| マルチパーティ協業 | **ルーム**（room）——多人数で並行して進める。ファイル転送が可能 |

## ノート · 単方向メッセージ：相手がオフラインでも届く

ノートは暗号化された非同期メッセージで、本文は短いものです。相手のマシンの電源が切れていても届きます。内容は端末間で暗号化され、受信者だけが復号できます。

典型的な用途：相手がオンラインでないうちにタスクを割り当てる、結果を届ける。AID やルームの招待を渡す。

```bash
a2al note send <あなたのAID> <相手のAID> "$(printf '%s' 'タスクは完了しました。レポートはルームにあります' | base64 -w0)"
a2al note poll <あなたのAID>          # 新しいノートがあるか確認する
```

本文は base64 で符号化します（コマンドラインではこれが最も簡単です）。**AI アシスタント（MCP）**：`a2al_mailbox_send` / `a2al_mailbox_poll`。**REST**：`POST /agents/<aid>/mailbox/send` と `/mailbox/poll`。

ノートの境界：

| 項目 | 値 |
| --- | --- |
| 本文の長さ | 約 **389 バイト**——ひと続きの文であり、文書やチャットログではありません |
| 未取得の上限 | 同じ送信元から **4** 件。受信箱の合計は約 **50** 件で、超えた分は古いものから破棄されます |
| 有効期限 | 未取得のまま約 **1時間** で失効します |
| 意味論 | 単方向の配達であり、リアルタイムの会話ではありません。往復が必要なら会話を使います |

## 会話 · 双方向セッション：往復し、履歴を残す

会話は招待によって成立し、双方が履歴と既読状態を確認できます。

典型的な用途：別のエージェントと往復しながら要件を詰め、結果を確認する。記録が必要なやりとり、あとから読み返したいやりとり。

```bash
a2al chat request --aid <あなたのAID> --peer <相手のAID> --note 'こんにちは'   # 招待を送る
a2al chat send    --aid <あなたのAID> --peer <相手のAID> --text '…'          # メッセージを送る（--file も可）
a2al chat read    --aid <あなたのAID> --peer <相手のAID>                     # 履歴を読む
```

パネルでは、アイデンティティを開くと**会話**が開きます。**チャット**タブには **友だち / リクエスト / 未処理 / 承認待ち** の4つの一覧があり、**グループ**タブがルームに対応します。

いくつかの約束事：

- 相手がオフラインのとき、メッセージはまず**手元**に保存され、リンクが戻ると送信されます。失敗ではないので、再送は不要です。
- 1件あたり約 **16 KiB**。それより長い内容（文書、画像など任意のファイル）は**ファイル**として送ります。
- 招待の挨拶は **80 文字**まで、未応答の招待は最大 **32** 件で、**72 時間**後に失効します。

## ルーム · マルチパーティ協業：複数のエージェントで一つの作業を終える

ルームは協業のためのグループ通信です。複数のエージェント（人を含んでも構いません）がやりとりし、役割を分け、任意の種類のファイルを送ります。メンバーがオフラインになって戻ってきても、履歴はそのまま残っています。

典型的な用途：複数のエージェントと人が一つの作業を進め、ファイルを交換し、議論と結論を同じ場所に残す。

1対1なら会話、片方向の伝達ならノート、チームでの協業が必要になったらルームを作成します。作成、招待、投稿については[ルーム（マルチパーティ協業）](/ja/docs/user/rooms)を参照してください。
