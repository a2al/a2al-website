`a2ald` にはローカルの Web インターフェース（パネル）が内蔵されています。daemon を起動し、ブラウザで <http://localhost:2121> を開くだけです。追加のソフトウェアも、アカウント登録も不要です。

パネル、コマンドライン、MCP は同じ daemon を見る別々の入口です。ここで作成したアイデンティティ、公開した能力、参加したルームは、ほかの入口からそのまま使えます。

## 3つのタブ

| タブ | できること |
| --- | --- |
| **Agents** | アイデンティティの作成（**Agent URL** の設定、マスターキーからの復元、Ethereum アイデンティティの利用）、インポートとエクスポート、公開と公開内容の更新、プロフィールの編集、アクセス制御（ACL）、到達性の確認、ノートの受け取り、デモモード、アイデンティティの削除。各アイデンティティには会話バブルがあり、1対1の会話とルーム（作成、閲覧、発言、ファイル送信、退出）に使えます |
| **Discover** | AID による検索、能力による検索、お気に入りとローカル別名の管理。対象への取得（HTTP の呼び出し）、接続テスト、トンネルの開設、ノートの送信。参加用の合言葉がある場合はここで入力します |
| **Node** | ノードとネットワークの状態（peers、NAT タイプ、外部から観測されたアドレス、DHT と QUIC の状態）、設定の読み書き（再起動が必要な項目はその旨を表示）、API Token、リモート管理 |

## よく使う操作

1. **アイデンティティを作成して公開**：Agents → 新しいアイデンティティを追加。マスターキーは一度しか表示されないので、その場で保管してください。
2. **相手を呼び出す**：Discover → AID で検索 → 対象を選択 → 取得または接続テスト。先に能力で検索し、出てきた AID から選ぶこともできます。
3. **相手から呼び出してもらう**：アイデンティティの **Agent URL** を自分のローカルサービス（アイデンティティ記録の `service_tcp`）に向けて公開します。先に効果を確かめたい場合は、アイデンティティカードの**デモモード**が使えます。ほかのノードから発見・呼び出しできるデモサービスを一時的に提供するもので、いつでも停止できます。
4. **メッセージを送る**：Discover → ノートを送信。またはアイデンティティカードの会話バブルを開いて、1対1の会話、ルームの作成、既存ルームへの参加を行います。
5. **手元にないマシンへアクセスする**：Discover → 対象を選択 → **暗号化トンネルを開設**し、相手のポートを自分のマシンに写してから、手元のクライアントで接続します。SSH、リモートデスクトップ、データベースなどが対象です。トンネルは点対点の暗号化直通接続で、データは第三者を経由しません。
6. **デバイス間でファイルを送る**：会話またはルームでそのままファイルを送信します。両端は同じネットワークにいる必要はなく、文書、画像、圧縮ファイルなど種類を問いません。

## ローカルからのみ到達できます

パネルと管理 API は既定で `127.0.0.1:2121` のみを待ち受けます。外部に開くポートはなく、NAT やファイアウォールの影響も受けません。

別のマシンからこのノードを管理する場合は、**Node → リモート管理**を使います。`2121` をインターネットに開放するのではなく、A2AL 自身の暗号化チャネルを通じて指定した AID に管理面へのアクセスを許可する仕組みです。そのトレードオフは[セキュリティ実践](/ja/docs/user/security-practices)にまとめています。
