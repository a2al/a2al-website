> **状态：草案。** 本页给出 A2AL 的地址版本字节空间、当前登记值与新分配的申请流程；政策与取值可能调整。

## 地址结构

A2AL 的 `Address` 是固定的 **21 字节**：

```
[ 版本字节 (1 字节) ][ 哈希 (20 字节) ]
```

版本字节编码**密钥算法与 20 字节哈希的派生方法**，不标识某条区块链——共享同一密钥算法与派生方法的多条链，映射到同一个版本字节。

DHT 的 `NodeID` 由地址派生：

```
NodeID = SHA-256(版本字节 ‖ 20 字节哈希)
```

## 版本字节空间

版本字节空间为 `0xA0`–`0xAF`（共 16 个值）。

| 区间 | 状态 | 政策 |
| --- | --- | --- |
| `0xA0`–`0xA7` | 正式 | 需专家评审（见下） |
| `0xA8`–`0xAD` | 保留 | 冻结；仅供未来的标准流程使用 |
| `0xAE` | 实验 | 无需登记；不保证唯一性 |
| `0xAF` | 私有 | 无需登记；不保证唯一性 |

## 当前分配

| 版本字节 | 名称 | 密钥算法 | 20 字节派生 | 典型用途 |
| --- | --- | --- | --- | --- |
| <span class="nowrap">`0xA0`</span> | `Ed25519` | Ed25519 | `SHA-256(pubkey)[0:20]` | A2AL 原生身份 |
| <span class="nowrap">`0xA1`</span> | `P256` | P-256 (NIST) | `SHA-256(pubkey)[0:20]` | A2AL 原生 P-256 身份 |
| <span class="nowrap">`0xA2`</span> | `Paralism` | secp256k1 | `RIPEMD160(SHA-256(pubkey))` | Paralism、Bitcoin P2PKH、Cosmos SDK、Litecoin |
| <span class="nowrap">`0xA3`</span> | `Ethereum` | secp256k1 | `Keccak-256(pubkey)[12:32]` | Ethereum 及全部 EVM 兼容链 |
| `0xA4`–`0xA7` | — | — | — | 未分配 |

> **关于 `0xA2`（Paralism）**：它是「secp256k1 + HASH160」派生族的命名代表。任何使用相同密钥算法与派生方法的链都与该版本字节兼容；名称来自第一个正式集成的链，不表示排他。

## 申请流程

申请未分配的版本字节（`0xA4`–`0xA7`）请使用 **Address Version Request** 模板开 GitHub Issue，包含：

1. **名称**——该版本字节的短标识（通常是链或算法名）；
2. **密钥算法**——如 Ed25519、secp256k1、P-256、Sr25519；
3. **20 字节派生**——由公钥映射到 20 字节的精确函数，附规范引用；
4. **签名验证**——如何用该密钥类型验证任意字节的签名；
5. **理由**——为什么现有版本字节无法覆盖该用例；
6. **代表链或实现**——至少一个具体使用者。

由 A2AL 维护者按**专家评审**政策评审。通过标准：

- 密钥算法与派生方法未被现有分配覆盖；
- 派生确定且恰好产出 20 字节；
- 存在该密钥算法的规范性公开说明；
- 请求不重复、不投机。

获批后合并进本文，并同步到代码常量。

## 实验与私有用途

- **`0xAE`（实验）**：可自由用于原型与测试。跨实现不保证唯一。不要用于生产。
- **`0xAF`（私有）**：用于不要求全局唯一的封闭或内部部署，实现可自行分配。

## 保留区间

`0xA8`–`0xAD` 已冻结，只有在未来标准流程启动、且正式池（`0xA0`–`0xA7`）接近耗尽时才会分配。当前政策下不接受指向该区间的申请。

## 与链身份的关系

版本字节标识的是**密码学方案**，不是某条链。共享同一密钥算法与派生方法的两条链（如 Paralism 与 Bitcoin SDK），由同一公钥会得到相同的 A2AL 地址。链相关上下文（如应用需要）放在端点记录或应用层，而不放进地址本身。
