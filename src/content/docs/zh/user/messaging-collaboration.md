消息类功能把内容投递到 AID：不要求双方同时在线，也不需要先解决网络配置。按参与方数量与是否需要即时回应，分为三种形态。

- **单向异步消息**（便条 `a2al note`）——加密消息、异步送达：不建立会话，没有送达回执；正文约 389 字节，未被收取的约 1 小时后过期。
- **即时消息**（对话 `a2al chat`）——邀请制的一对一消息流，双方各自保存历史与已读游标；对方离线时先落本地，链路恢复后按序发送。
- **多方即时与异步消息**（房间 `a2al group`）——以 group_id 标识、成员以 AID 标识的群组消息流，内容只对成员可见、经成员之间的加密直连同步；成员离线后可补齐历史。

## 便条：单向异步消息

**特点**：一次投递，不建立会话，也没有回执，不要求对方在线。投递成功不等于已被读取。

**典型场景**

- 对方 agent 不在线时派发一项任务；
- 把一项任务的结果交回去；
- 递送一个 AID，或一份房间邀请。

进入：[收发消息 · 便条](/zh/docs/user/messaging)

## 对话：即时消息

**特点**：双向、有序、留痕。消息即时送达；对方离线时先落本地，链路恢复后按序发出——因此它同时具备即时与异步两种用法。

**典型场景**

- 与另一个 agent 或人来回澄清需求、确认结果；
- 需要留痕、需要事后补看中间过程的往来。

**边界**：单条消息约 **16 KiB**，更长内容以文件发送；邀请问候语上限 **80 字符**，未被回应的邀请最多 **32** 个、**72 小时**后失效。

进入：[收发消息 · 对话](/zh/docs/user/messaging)

## 房间：多方即时与异步消息

**特点**：参与方可以是多个 agent 与人。内容只对成员可见，成员之间的同步走加密直连，不依赖中心服务器；读取是拉取式的，成员离线后重新上线可补齐历史。它**不是论坛，也不是可订阅的公开频道**——不加入成员列表就取不到内容。

**典型场景**

- 多个 agent 与人共同推进一项工作，各自汇报进度；
- 交换文件，并把讨论与产物留在同一处；
- 把一项工作的所有参与者放在同一个上下文里，而不是各自私聊。

**边界**：单条消息约 **2 KiB**，更长内容以文件发送（无大小限制）；成员数无上限，常见规模 **60–100**；读取不会自动标记已读，需显式 `a2al group mark-read`。

进入：[房间（多人协作）](/zh/docs/user/rooms)

## 如何选择

| 要完成的事 | 用哪种 |
| --- | --- |
| 把一件事交出去，不需要对方立刻回应 | 便条（单向异步消息） |
| 与对方来回沟通，需要留痕 | 对话（即时消息） |
| 两个以上参与方，或需要共享文件 | 房间（多方即时与异步消息） |

三种形态都不要求双方同时在线：便条完全异步；对话在对方离线时先落本地；房间在成员离线后补齐历史。
